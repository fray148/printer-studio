# Printer Studio — самостоятельный форк Creator 5 Pro Dashboard

Доработка текущей панели на основе upstream 1.4.0, с сохранением её оформления,
страницы материалов и управления камерой. Новые разделы: таймлапсы и Telegram.

## Размещение

- Адрес: **http://192.168.1.35:5012/**.
- Принтер: Creator 5 Pro, **192.168.1.98**, штатная прошивка 2.0.0.
- Compose-проект и контейнер: `printer-studio`.
- Каталог сервера: `/home/fray/apps/printer-studio`.
- Прямое подключение к принтеру по штатному HTTP API. Z-Mod и Moonraker не нужны.
- Панель на 5011 не является зависимостью. Её остановка не останавливает этот форк.
- Собственные `.env`, сеть Compose и каталог `data`; общих файлов с 5011 нет.

В штатной камере ограничено количество клиентов. Внутри этого форка просмотр,
запись и Telegram используют одно общее подключение. Во время записи в новой
панели не открывай отдельный поток камеры в старой панели или другом приложении.

## Что добавлено

**На главной:** состояние таймлапса и бота, переход к управлению записью,
кнопка **«Файлы таймлапсов →»**.

**Таймлапсы:** ручной запуск и остановка; автоматическая запись при печати;
пауза печати не завершает видео; просмотр MP4 в браузере; повторная сборка после
ошибки. Сборка через FFmpeg: H.264, yuv420p, ширина не более 1280, один поток.
Очередь кодируется последовательно.

**Файлы записи:** скачать MP4, скачать исходные JPEG в ZIP, скачать описание JSON,
переименовать и удалить запись вместе с исходниками. Удаление с подтверждением;
идущую запись и собираемое видео удалить нельзя. ZIP передаётся потоком без
создания второй копии архива на диске.

**Telegram:** включается после создания бота. В панели вводятся токен и разрешённый
`chat_id` на отдельной вкладке **«Бот»** (`/bot`), есть тестовое сообщение. Команды `/status`, `/photo`, `/timelapse`,
`/help`. Уведомления о начале, паузе, остановке/завершении, ошибках и прогрессе.
Готовые видео до 49 МиБ можно получать автоматически; более крупные скачиваются
из панели. Управления движением, нагревом или запуском печати через бота нет.
При сетевых ошибках сообщения повторяются до пяти раз; очередь хранится на диске.

Если состояние принтера меняется с печати на `idle`, бот сообщает об остановке,
а не объявляет успешное завершение без подтверждающего статуса.

## Начальные настройки

| Параметр | Значение |
|---|---|
| Автоматическая запись | выключена |
| Telegram | выключен |
| Интервал снимков | 10 секунд |
| Частота видео | 25 FPS |
| Срок хранения | 30 дней после окончания записи |
| Лимит архива, включая исходные кадры | 10 ГиБ |
| Минимум свободного места | 2 ГиБ |
| Уведомления о прогрессе | каждые 25% |
| Ограничение контейнера | 1 CPU, 768 МиБ RAM |

По сроку хранения автоматически удаляются завершённые и неудачные записи с их
исходниками. При нехватке места запись останавливается, активные записи не
вытесняются. Лимит проверяется перед кадрами и сборкой; временный файл кодирования
может ненадолго увеличить размер архива сверх установленного лимита.

При пересоздании контейнера настройки, очередь Telegram, архив, материалы и
история остаются в `./data`. Незавершённая запись продолжается с сохранённых
кадров; пропущенное за время простоя восстановить нельзя. Прерванная сборка
ставится в очередь заново. Для сохранности данных не удаляй каталог `data`.

## Docker

В каталоге проекта на сервере:

```sh
docker compose -p printer-studio -f docker-compose.yml up -d --build
docker compose -p printer-studio -f docker-compose.yml ps
docker compose -p printer-studio -f docker-compose.yml logs --tail=100
```

Повторный запуск без пересборки:

```sh
docker compose -p printer-studio -f docker-compose.yml up -d
```

Остановка только этого форка:

```sh
docker compose -p printer-studio -f docker-compose.yml stop
```

`.env` создаётся по `.env.example`. Реальные серийный номер и код доступа не
включены в проект. При установке их можно скопировать из существующей панели
на сервере, не меняя её конфигурацию. Ключи Telegram сохраняются отдельно в
`data/automation/settings.json` с правами 0600 и не возвращаются API браузеру.
Токен и `chat_id` вводятся позже на вкладке **«Бот»**: http://192.168.1.35:5012/bot.

Новый проект не меняет Nginx Proxy Manager и TinyAuth. Порт 5012 доступен в
локальной сети; для доступа извне подключается существующая схема NPM/TinyAuth.

## Проверки

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -q
node --check static/automation.js
node --check static/automation-home.js
```

Проверяются запись и восстановление кадров, переходы состояний, ограничения
места, срок хранения, защита удаления и путей, CSRF, отсутствие токена в ответах,
отказ чужому `chat_id`, очередь повторной отправки, ZIP и скачивание файлов.
Есть настоящая сборка тестового MP4 с FFmpeg и проверка HTTP Range для плеера.
Интеграция с Telegram до создания настоящего бота проверяется с подставными
ответами; фактическую отправку нужно проверить после ввода токена.

Локальный просмотр без обращения к принтеру:

```sh
.venv/bin/python scripts/preview.py
```

Адрес предпросмотра: http://127.0.0.1:55011/. Данные там демонстрационные,
настройки и пробные записи временные.

Исходный README upstream оставлен в `README.md`; указания выше относятся к форку.
